# PRD: The Maid — Local-First AI File Organizer & Digital Asset Manager

## Problem Statement

Users have chaotic file systems — messy Desktops, overflowing Downloads, unorganized Documents. Manually sorting hundreds or thousands of files is tedious and error-prone. Existing solutions either require cloud uploads (privacy risk) or are too simplistic (rule-based only, no intelligence).

**The user needs:** A privacy-first desktop app that intelligently proposes file organization, lets them approve every move, and permanently tags files for native OS search — all without ever sending data to the cloud.

## Solution

"The Maid" is a native desktop app that:
1. Scans user-defined folders (sandboxed to Desktop/Downloads/Documents/Pictures)
2. Extracts metadata (EXIF, OCR, text) from files
3. Uses a local LLM to generate a structured "Cleanup Plan" (proposed moves + tags)
4. Presents a Human-In-The-Loop (HITL) approval UI — user reviews and checks/unchecks items
5. Executes approved moves and injects IPTC/XMP metadata for native search
6. Optionally clusters faces in photos and lets the user name them retroactively

**Pricing:** Free with optional donation. Honor system — no DRM, no server, no telemetry.

## User Stories

1. As a user with a messy Desktop, I want The Maid to scan my folders and propose organization, so that I don't have to manually sort files.
2. As a privacy-conscious user, I want all processing to happen locally, so that my financial documents and personal photos never leave my machine.
3. As a user reviewing proposed moves, I want to uncheck individual items, so that The Maid doesn't move files I want to keep in place.
4. As a photographer, I want face clustering that works without pre-training, so that I can group photos of the same person and name them later.
5. As a user who paid for v1, I want bug fixes for free forever, so that I'm not forced to upgrade for stability.
6. As a user who wants new features, I want to pay a delta upgrade fee, so that I only pay for the value I receive.
7. As a user installing The Maid, I want to select which features I need during setup (PDF, faces, general files), so that I don't download models I won't use.
8. As a user with system directories, I want The Maid to hard-reject any attempt to scan/modify system folders, so that I trust it won't damage my OS.
9. As a user renaming a bucket, I want the actual folder on disk to rename too, so that my file system stays consistent.
10. As a user encountering an error, I want The Maid to speak in third person during technical failures, so that errors feel clear rather than broken persona.
11. As a user with no files in my sandbox, I want The Maid to simply say "I found nothing to organize" rather than crash or force me to create dummy files.
12. As a user checking for updates, I want a manual "Check for Updates" button, so that The Maid never phones home without my explicit request.
13. As a user donating to support development, I want a simple "Support The Maid" link in Settings, so that I can contribute if I value the app.
14. As a developer, I want a strict JSON schema for the Cleanup Plan, so that the Python backend and Tauri frontend have a reliable contract.
15. As a user approving a batch, I want per-file atomicity, so that if one move fails the rest still succeed and I can retry the failed item.

## Implementation Decisions

### Architecture
- **Frontend:** Tauri (React + Rust) — native desktop feel, cross-platform path for v2
- **Backend:** Python bundled as Tauri sidecar process — spawned by Rust, communicates via Tauri event system (`emit`/`listen`)
- **Communication:** No HTTP ports, no stdin parsing. Tauri `Command` API + events for real-time scan progress

### Model Distribution
- **Always bundled:** Text LLM (~500MB) — core file organization works offline immediately
- **Optional during setup:** Face models (~100MB) + Vision/OCR model (~1GB) — user selects features, models download during install
- **Installer:** NSIS (Tauri-integrated) with custom wizard for folder selection and feature selection

### Data & Persistence
- **User settings:** Tauri Store (encrypted, cross-platform, OS-native backup)
- **Face embeddings:** Local SQLite (`~/.the-maid/face-index.db`) — machine-facing data only, not searchable metadata
- **Image metadata:** IPTC/XMP tags written via ExifTool — human-readable, searchable by native OS

### Sandbox & Security
- **Allowed paths:** User-defined folders (default: Desktop, Downloads, Documents, Pictures)
- **Enforcement:** Hard reject for system directories — Rust validates all paths before Python executes
- **Scan gate:** Scan button disabled until ≥1 folder is selected for scanning

### JSON Schema (Cleanup Plan)
```json
{
  "schema_version": "1.0.0",
  "plan_id": "uuid",
  "created_at": "ISO-8601",
  "files": [
    {
      "file_id": "8-char-hex",
      "original_filename": "string",
      "current_path": "absolute-path",
      "proposed_path": "absolute-path",
      "proposed_tags": ["tag1", "tag2"],
      "faces_detected": ["Unknown_Person_01"],
      "rationale": "string",
      "user_edited_path": "absolute-path (optional)"
    }
  ]
}
```
- `file_id`: 8-char hex (short hash of `current_path`)
- All fields required except `user_edited_path`
- `faces_detected`: always present, empty `[]` if none

### Execution Model
- **Per-file atomicity:** Each approved move is independent
- **Partial execution expected:** Report per-file status, allow retry of failed items
- **No rollback:** Filesystem doesn't support transactions across moves

### Persona & Tone
- **Normal operation:** First person — "I found 47 files", "I suggest moving these to..."
- **Technical errors:** Third person fallback — "The Maid encountered an error. Please restart the application."

### Licensing & Revenue
- **No DRM:** Honor system with optional donation
- **Bug fixes:** Free forever for purchased version
- **New features:** Paid upgrade (delta pricing: user pays difference between original purchase and new version price)
- **Updates:** Manual "Check for Updates" only, plus newsletter/email announcements

## Testing Decisions

- **Unit tests:** Python backend — scanner, sandbox validation, metadata extraction, face clustering pipeline
- **Integration tests:** Tauri sidecar spawn/kill, event emission, IPC contract (JSON schema validation)
- **E2E tests:** Full scan → approval → execution flow with temp directories
- **Sandbox tests:** Attempt to escape sandbox (system paths, symlinks, relative paths) — must all fail
- **Persona tests:** Verify first-person in normal flow, third-person in error states

## Out of Scope

- macOS/Linux support (v2)
- Cloud sync or backup
- Multi-user / network shares
- Real-time file system monitoring (watch mode)
- Plugin/extension system
- Mobile companion app
- Server-based activation or DRM
- Automatic background updates

## Further Notes

- **Windows code signing:** Budget ~$200/yr (Certum/SSL.com) for MSI/EXE signing
- **Face clustering UX:** Need clear thumbnail grid for "Unknown_Person_N" clusters before naming
- **Model download UX:** Progress bar during NSIS install, resume on failure
- **Empty state UX:** Graceful handling of zero files, zero buckets, zero face detections
- **Performance target:** Scan 10,000 files in <30 seconds on mid-range hardware
- **Memory target:** Peak usage <2GB during face clustering (batch processing, not all-at-once)
